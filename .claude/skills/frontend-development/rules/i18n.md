# Локализация

## Строк в разметке нет — есть ключи

Интерфейс двуязычный: русский первичный и лежит в бандле, английский подгружается лениво. Любой новый текст добавляется в **оба** файла `i18n/messages/{ru,en}.ts`.

```ts
const { t } = useI18n();
```

```html
<h1>{{ t('projects.title') }}</h1>
<AppButton>{{ t('common.save') }}</AppButton>
```

Единственные намеренно непереводимые строки: `APP_NAME = 'Task Management'` в `router/guards.ts` (бренд, совпадает с `config('app.name')`) и `ACCOUNT_DISABLED_PREFIX` в `api/errors.ts` (привязка к ответу бэкенда).

## `ru.ts` — источник схемы, `en.ts` типизирован по ней

`en.ts` объявлен как `MessageSchema`, поэтому забытый ключ роняет `vue-tsc`, а не прод. Правила из шапки `ru.ts` обязательны:

- никакого `as const` — иначе типом ключа станет русский литерал и `en.ts` перестанет компилироваться;
- максимум 3 уровня вложенности — vue-i18n разворачивает пути ключей рекурсивно на уровне типов;
- `@` и `|` зарезервированы (связанные сообщения и плюрализация) — в обычном тексте их быть не должно;
- модуль не импортирует ничего, чтобы не создать цикл через `api/errors.ts`.

Ключи группируются по разделу (`common`, `nav`, `routes`, `errors`, `enums`, `projects`, `tasks`, `users`, ...). Общий текст — в `common`, не дублируй его в разделе.

Проверка ключей в шаблонах работает благодаря `declare module 'vue-i18n' { interface DefineLocaleMessage extends MessageSchema {} }` в `i18n/index.ts`.

## `useI18n()` в компонентах, `i18n.global.t` вне их

`normalizeError` вызывается из интерсептора axios, а guard'ы регистрируются вне компонента — там инстанса компонента нет, и `useI18n()` бросит исключение.

## Множественное число — три формы, через `ruPluralRule`

Русская плюрализация подключена как `pluralRules: { ru: ruPluralRule }` (`one | few | many`). Правило клампит индекс по `choicesLength`, чтобы сообщение могло нести меньше трёх форм — русский текст часто обходится одной, тогда как английский несёт две. Растиражированные в интернете версии правила рассчитаны на четырёхформное `zero | one | few | many` и промахиваются на единицу — не подменяй реализацию.

Счёт передаётся третьим аргументом, отдельно от подстановок:

```ts
t('throttle.retryIn', { n: secondsLeft.value }, secondsLeft.value);
```

```ts
// ru.ts — одна форма
retryIn: 'Слишком много попыток. Повторите через {n} с.',
// en.ts — две
retryIn: 'Too many attempts. Try again in {n} second. | Too many attempts. Try again in {n} seconds.',
```

## Подписи enum не хранятся в TypeScript

`types/enums.ts` содержит только значения и типы; подписи живут в локалях под `enums.<группа>.<значение>` и читаются через `useEnumLabel()`.

```ts
const { enumLabel, enumOptions } = useEnumLabel();

const statusOptions = enumOptions('projectStatus', PROJECT_STATUSES);
```

`enumOptions` возвращает `ComputedRef`, иначе подписи «замёрзнут» на языке, активном в момент `setup()`. `enumLabel` падает на сам slug через `te()`, если ключа нет: статус, добавленный на бэкенде, отрендерится как `in_review`, а не как `undefined` или путь ключа.

## Смена языка — только через `setLocale`

`setLocale(code)` догружает сообщения, обновляет `i18n.global.locale`, реактивный `activeLocale`, `document.documentElement.lang` и сохраняет выбор. `bootstrapLocale()` вызывается в `app.ts` **до** монтирования приложения.

Выбор хранится под ключом `tm.locale` отдельно от сессии, потому что `clearSession()` не должен сбрасывать язык при выходе. Каждый доступ к `localStorage` обёрнут в `try` — в приватном режиме Safari он бросает исключение. Порядок определения: сохранённый выбор → `navigator.languages` → русский.

## Даты и числа — через `Intl`, а не руками

`utils/format.ts` форматирует всё по реактивному `intlLocale` (`ru-RU` / `en-GB`), поэтому шаблоны перерисовываются при смене языка сами. Пустое значение даёт `—`, некорректное возвращается как есть.

```ts
formatDate(project.created_at);      // 15.07.2026
formatDateTime(task.updated_at);     // 15.07.2026, 10:30
fullName(project.creator);
```

Не собирай дату строковыми операциями и не подключай date-библиотеку.
