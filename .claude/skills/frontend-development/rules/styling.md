# Стили

За синтаксисом и утилитами Tailwind v4 — скилл `tailwindcss-development`. Здесь только то, что специфично для этого приложения.

## Конфиг-файла нет: тема живёт в `resources/css/app.css`

Tailwind v4 в CSS-first режиме, подключён через `@tailwindcss/vite`. Файл целиком:

```css
@import 'tailwindcss';

@source '../../vendor/laravel/framework/src/Illuminate/Pagination/resources/views/*.blade.php';
@source '../../storage/framework/views/*.php';
@source '../js/**/*.{vue,ts}';

@custom-variant dark (&:where(.dark, .dark *));

@theme {
    --font-sans: 'Instrument Sans', ui-sans-serif, system-ui, sans-serif, ...;
    /* семантические токены цвета — см. ниже */
}

:root { color-scheme: light; }
.dark { color-scheme: dark; /* те же токены в тёмных значениях */ }
```

Не создавай `tailwind.config.js` — он не будет прочитан. Токены темы правятся в `@theme`, новые сканируемые пути добавляются директивой `@source`.

Тёмные значения задаются обычным правилом `.dark`, а не вторым `@theme`: подмена должна работать в рантайме через каскад, поэтому утилиты обязаны компилироваться в `var(--color-*)`. По той же причине здесь нельзя `@theme inline`.

## Утилиты пишутся в разметке, `@layer components` не заводится

Ни одного блока `<style>` и ни одного собственного класса-компонента в проекте нет. Повторяющееся оформление выносится в компонент или в карту вариантов (`components.md`), а не в CSS-класс.

Классы должны оставаться цельными строками в исходнике — сканер Tailwind не выполняет код, поэтому `` `bg-${color}-600` `` не соберётся.

## Палитра зафиксирована в токенах

Оттенков Tailwind (`gray-900`, `indigo-600`) в разметке нет — только семантические токены. Каждый из них имеет светлое и тёмное значение, поэтому одна и та же строка классов работает в обеих темах.

| Роль | Токен | Светлая / тёмная |
| --- | --- | --- |
| Фон страницы | `bg-canvas` (задан в `app.blade.php`) | `gray-50` / `gray-950` |
| Карточка, таблица, меню, поле | `bg-surface` + `ring-1 ring-border`, скругление `rounded-lg` | `white` / `gray-900` |
| Шапка таблицы, вторичный фон | `bg-surface-muted` | `gray-50` / `gray-800` |
| Ховер, чип, колонка доски | `bg-surface-hover` | `gray-100` / `gray-800` |
| Границы и разделители | `border-border`, `ring-border`, `divide-border` | `gray-200` / `gray-800` |
| Обводка поля ввода | `ring-border-strong` | `gray-300` / `gray-700` |
| Текст | `text-fg` основной, `text-fg-muted` вторичный, `text-fg-subtle` подписи, `text-fg-faint` плейсхолдеры | |
| Основное действие | `bg-accent` / `hover:bg-accent-hover`, ссылки `text-accent-fg` | `indigo-600` / `indigo-500` |
| Опасное действие | `bg-danger` / `hover:bg-danger-hover`, ошибки `text-danger-fg` | `red-600` / `red-500` |
| Тона бейджей и алертов | `emerald` успех, `amber` ожидание, `blue` в работе, `red` ошибка, `gray` нейтральное | |

Не вводи новый оттенок ради одного элемента — возьми существующую роль. Новый токен добавляется сразу в оба блока `app.css`.

## Тёмная тема: нейтрали через токены, `dark:` только в картах вариантов

Класс `dark` вешается на `<html>`. Его ставит инлайн-скрипт в `app.blade.php` до загрузки стилей (иначе первый кадр был бы светлым) и дальше синхронизирует стор `stores/theme.ts` поверх `utils/theme.ts` (ключ `tm.theme`, режимы `light` / `dark` / `system`). Переключатель — `components/layout/ThemeSwitcher.vue`, стоит рядом с `LocaleSwitcher` в `AppShell.vue` и в `App.vue`.

Правило одно: **нейтральный цвет — всегда токен, `dark:`-вариант для него не пишется**. Точечный `dark:` допустим только там, где токена нет по смыслу:

- цветные тона в картах вариантов (`AppBadge`, `AppAlert`) — светлая заливка `bg-blue-50` в тёмной теме заменяется прозрачной `dark:bg-blue-500/10`;
- инверсия (`AppToastHost`, нейтральный тост) и затемнение подложки (`AppModal`, `AppDrawer`).

Точечный `dark:` на обычной странице — ошибка: так получается полутёмный интерфейс. Проверка — `grep -rE '\b(bg|text|border|ring|divide)-(white|gray)-' resources/js` не должен находить ничего, кроме этих карт.

## Адаптивность: mobile-first и скупая

Брейкпоинтов в проекте всего около полутора десятков, только `sm:`/`md:`/`lg:`. Базовые стили — мобильные, брейкпоинт добавляется, когда без него верстка ломается.

Устоявшиеся приёмы:

- Шапка: десктоп-навигация `hidden md:block`, кнопка-бургер `md:hidden` открывает `AppDrawer` с той же `AppNav` в колонку (`AppShell.vue`).
- Ширина контента: `mx-auto w-full px-4 py-6` + `max-w-6xl`, переключаемая на `max-w-7xl` флагом `ui.wideContent`.
- Сетки фильтров и форм: `grid gap-4 sm:grid-cols-2 lg:grid-cols-4`.
- Ряды заголовков и кнопок: `flex flex-wrap items-center justify-between gap-3` — переносится сам, брейкпоинт не нужен.
- Таблицы оборачиваются в `overflow-x-auto` вместе с `ring`, чтобы прокручивалась таблица, а не страница.

Горизонтальная прокрутка страницы — баг. Абсолютно спозиционированный или `sr-only` элемент внутри таблицы уже приводил к сдвигу.

## Фокус и состояния

Кнопки и интерактивные элементы несут `focus-visible:outline-2 focus-visible:outline-offset-2` с цветом под вариант; `disabled:cursor-not-allowed disabled:opacity-60` для заблокированного состояния. Не убирай контуры фокуса.
