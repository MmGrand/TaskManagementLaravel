# Состояние и роутинг

## Pinia: только setup-сторы, и их всего три

`auth`, `ui`, `locale` — объявлены как `defineStore('name', () => { ... })` с `ref`/`computed` внутри и явным `return`. Option-синтаксиса здесь нет.

Стор заводят под глобальное состояние, переживающее навигацию. Данные экрана (список, метаданные страницы, флаги загрузки) живут в `ref` внутри `*View.vue` — выносить их в стор не нужно.

## `auth` — зеркало сессии, восстанавливается один раз

Токен и пользователь кэшируются в localStorage через `utils/tokenStorage`. `bootstrap()` идемпотентен (`bootstrapped` защищает от повторов) и вызывается из guard'а роутера, а не из компонентов.

Сетевая ошибка или 500 при восстановлении оставляют закэшированную сессию — приложением можно пользоваться дальше; сессия чистится только на 401 и на заблокированный аккаунт.

`can(permission)` отражает `User::hasPermission` из `app/Models/User.php`: неактивная роль не имеет прав вообще, `*` даёт все.

## `ui` — тосты и ширина контента

```ts
ui.success(t('projects.created'));
ui.error(apiError.message);
```

Тосты автоматически гаснут через 5 секунд, одновременно видно не больше четырёх, лишние срезаются с начала. Флаг `wideContent` переключает `max-w-6xl` ↔ `max-w-7xl` в `AppShell` — его ставит доска задач.

## Маршруты: лениво + meta

```ts
{
    path: '/projects/:id(\\d+)',
    name: 'project',
    component: () => import('@/views/projects/ProjectShowView.vue'),
    meta: { requiresAuth: true, permission: 'projects.view', titleKey: 'routes.project' },
}
```

`RouteMeta` расширен в `router/routes.ts` четырьмя полями: `guestOnly`, `requiresAuth`, `permission` (типизировано `Permission`), `titleKey`. Числовые параметры ограничиваются `(\\d+)`. Навигация в шаблонах — через `:to="{ name, params }"`, а не строкой пути.

Добавляя маршрут: компонент лениво, `titleKey` в оба файла локалей, `permission` из `types/enums.ts`.

## Guard один, и он ждёт восстановление сессии

`guards.ts` регистрирует `beforeEach` (await `auth.bootstrap()`, затем meta-проверки) и `afterEach` (заголовок вкладки). Своих `beforeEnter` в маршрутах нет — логика доступа должна оставаться в одном месте.

Редиректы: гость на защищённом маршруте → `login` с `query.redirect`; авторизованный на `guestOnly` → `dashboard`; нет права → `forbidden`.

Заголовок вкладки собирается как `«<перевод titleKey> — Task Management»`; `APP_NAME` не переводится, он совпадает с `config('app.name')`. Отдельный `watch(activeLocale)` переставляет заголовок при смене языка, потому что сам он не перерисовывается.

## Права на клиенте скрывают UI, но ничего не решают

`usePermissions()` зеркалит gate'ы и policy бэкенда, каждая функция помечена комментарием со ссылкой на policy (`/** ProjectPolicy::update */`). `Gate::before` даёт админам всё, поэтому каждая проверка владения начинается с короткого замыкания через `isAdmin`.

```html
<AppButton v-if="permissions.canUpdateProject(project)" variant="ghost" @click="openEdit(project)">
```

Источник истины остаётся на сервере: 403 всё равно нужно обрабатывать. `ProjectPolicy::view` намеренно не отражён — он ходит в базу, и на клиенте не воспроизводится.

Меняя policy на бэкенде, поправь зеркало здесь — иначе UI покажет действие, которое упадёт.

## Списки: фильтры и страница живут в URL

`useListQuery(defaults, load)` держит `filters` и `page` синхронными с `route.query`, вызывает `load` на монтировании и на каждое изменение query.

```ts
async function load(): Promise<void> { /* дергает api, пишет в refs */ }

const query = useListQuery<{ status: ProjectStatus | '' }>({ status: '' }, load);
```

Дженерик указывается явно: нетипизированное `''` расширило бы тип фильтра до `string`.

- В URL попадают только значения, отличные от дефолтных — чтобы ссылка оставалась читаемой.
- Смена фильтра всегда сбрасывает на первую страницу (`applyFilters`).
- `per_page` не отправляется: репозитории захардкожены на 15 и игнорируют его.
- Пагинация — `<AppPagination :meta @update:page="query.goToPage" />`.
- Удаление последней строки на странице > 1 уводит на предыдущую, а не оставляет на пустой.

## Наполнение селектов сущностями

`useOptionsList(fetchPage, toOption)` обходит страницы (не больше пяти), потому что у API нет `?search=` и `per_page` игнорируется. Возвращает `truncated`, чтобы UI мог сказать про обрезанный список, и `failed` — 403 здесь норма (обычный пользователь не видит список пользователей), это не повод показывать ошибку.
